## 三、ATR 止损口径缺陷与影响（审计 D-8）

审计发现两处问题，均已修复：

1. **日线面板混合口径（D-8a）**：PIT 日线 `open/high/low` 为原始价、`close` 为前复权价
   （ADR-0002；实测 000001.SZ 2026-01-05：raw_close 11.50 / close 11.1336 / factor
   0.9681，high 11.51 low 11.41 为原始价）。真实波幅（TR）混用两者，在除权除息日的
   bar 上会得到荒谬的 ATR。修复：用逐 bar `adjust_factor` 把 high/low 换算到 close
   的口径（`PullbackPortfolio._adjust_factor_frame`）。
   **分钟数据不需要换算**：AlphaFeed 分钟接口返回的就是前复权价（同日缓存最后一笔
   11.1336 = PIT 前复权 close；raw 为 11.50），与账本/止损同口径，直接可比。
   *（2026-09-09 曾一度对分钟价再乘 factor，导致双重复权、止损提前触发，
   已回滚并加测试 `tests/test_pullback_atr_basis.py::test_minute_prints_are_compared_as_is`。）*
2. **TR 被压成一维（D-8b）**：`pd.concat([...], axis=1).max(axis=1)` 把
   `(date × symbol)` 压成按日期的 Series，`_atr_pct.loc[d, symbol]` 恒为 NaN，
   `_stop_dist` 于是**一直退化到 2.5% 地板**——配置里写的"ATR 自适应 2.5–4%"从未生效。
   修复：`np.maximum.reduce` 保留二维结构。

## 四、成交来源分离（审计 D-4）★

账本 `fills.source` 现在区分：

| source | 含义 |
| --- | --- |
| `live` | 实时交易者按当时成交价当场卖出（时间到秒） |
| `replay` | 分钟 bar 回放的日内止损（历史段） |
| `close` | 收盘调仓成交 |
| `auction` | 14:50 提交、15:00 集合竞价成交的委托 |

影子日报与面板都分别计数（`equity.fills_by_source`）。审计结论"96% 的日内止损是
回放"即由此可核。**不得再把 `replay` 计入"实时执行"**。

### 生产账本的实测口径（2026-09-08 收盘后）

| 项 | 数量 |
| --- | --- |
| 全部成交 | 252 |
| 日内成交（`time` 非空） | 55 |
| 其中 2026-09-04 之前（分钟回放） | **54** |
| 其中 2026-09-04 起（实时执行） | **1**（`2026-09-08 13:00:06 300832.SZ` 卖出） |

即**日内止损样本中 98.2% 是回放、仅 1 笔是实时执行**。`source` 列于 2026-09-09 起
写入（旧行为空 = 未标注，不追溯改写），因此：

- LIVE-EXEC 证据目前 **n = 1**，不足以支撑任何关于"实时执行效果"的结论；
- 任何把 55 笔日内成交当作"实时止损 55 次"的表述都是错的。

## 五、统计功效（不要把噪声当 alpha）

日频策略 Sharpe 的标准误 ≈ √(252/N)（N = 交易日数）：

| 样本 | Sharpe 标准误 | 说明 |
| --- | --- | --- |
| 80 日 | ≈ 1.78 | 观测 Sharpe 1.6 与 0 无法区分 |
| 165 日（2026 段） | ≈ 1.24 | 仍很宽 |
| 252 日 | 1.00 | 一年样本本身就不足以确认 SR≈1 |

要检出真实 Sharpe 1.0（α=0.05、power=0.8）约需 **1,556 个交易日 ≈ 6.2 年**；
检出 0.5 约需 **6,225 个交易日 ≈ 25 年**。因此：

- 任何单年数字（包括 OOS）都不构成"策略有效"的统计证据；
- `scripts/d_oos.py` 因此输出 `sharpe_standard_error` 与 `sharpe_t_stat`，
  而不是只报一个 Sharpe。

## 六、OOS 验证（审计 D-3）★

`scripts/d_oos.py` 用**生产同构装配**（`_shadow_cycle` → `_build_account_portfolio`）
在 fresh ledger 上重跑，并强制 14 项断言（2026-09-09 审计后加固；新增符号级窗口覆盖）：

1. `ledger_was_fresh` — 账本在运行前**不存在**（旧版断言的是"resumed 为 False"，而账本先被 unlink → 恒真）
2. `calendar_gap_within_tolerance` — 窗口内日历缺口 ≤ 15 天（容忍春节）
3. **`minute_symbol_coverage_ok`** — 每一天都有 ≥90% 标的带分钟特征（**符号级**，旧版只查日期级）
4. **`no_fills_inside_data_hole`** — 成交不得落在低覆盖日
5. `intraday_frames_loaded` — 分钟特征包已装配且含 `tail_vol`
6. `minute_provider_loaded` — 日内止损已装配
7. `assembly_is_production` — book 类型 + intraday/minute 接线 + kill-switch 接线与生产一致
8. `no_fill_after_window_end`
9. `intraday_fills_before_1500`
10. `live_dates_not_replayed` — 仅当窗口含实时日期时有意义（工件记录 `n_live_dates_in_window`）
11. `t_plus_1_respected`
12. `no_fill_on_limit_locked_bar`（方向感知）
13. `cost_model_consistent` — 账本佣金 = 逐笔佣金之和 = 指标佣金

另有两个**非断言**字段，用于防止把候选配置当成部署配置：

- `params_match_production` — 与**配置账户**（无 `--set`）构建的对照探针比较（旧版用同一份
  `--set` 自比较，任何候选都能通过）；
- `citable` — 仅当"fresh ledger + 全部断言通过 + `params_match_production` + 无 `--set`
  覆盖"时为 true。**只有 `citable=true` 的工件数字可以引用。**

**+1.64%（Sharpe 0.40）** 抬到 **+8.12%（Sharpe 1.58）** —— 缺口删掉了绝大多数沪市
机会集，留下的深市样本恰好表现更好。**回补后的数字才是可引用的 OOS 证据。**
回补由 `scripts/backfill_minute_gap.py` 完成（80 次 API 调用，约 5 分钟：
最小覆盖 273 → **794/800**，低覆盖日 35 → **0**）。

### 止损宽度在"干净窗口"上的重评（2026-09-09 收盘后）

| 变体 | IS 2026（Sharpe） | OOS 2025H2 干净（Sharpe / 累计 / t） | max-min |
| --- | --- | --- | --- |
| `flat_3p5`（部署） | **1.66** | 0.40 / +1.64% / 0.23 | 0.40 |
| `atr_1p0_25_40` | 0.97 | **0.65 / +3.38% / 0.37** | **0.65** |
| `atr_1p0_25_35` | 1.95 | 0.29 / +1.10% / 0.17 | 0.29 |
| `flat_2p5`（旧） | 1.53 | **−1.33 / −7.21% / −0.76** | −1.33 |

**两个稳健结论**：
1. **离开 2.5% 是稳健的**：旧宽度在两个窗口都是最差（OOS −7.2%、maxDD 11.4%），
   与"它是 TR 缺陷的产物、从未被主动选择"一致。
2. **在更宽的止损之间，排名随窗口翻转**（IS 上 flat_3p5 最好，OOS 上
   `atr_1p0_25_40` 最好），且所有差异都在噪声内（|t| ≤ 0.8，SE ≈ 1.75）。
   → **不再据此切换配置**：同一窗口已被用于一次选择，再用它选第二次只是把噪声
   当信号。`atr_1p0_25_40` 记为**候选**，等前向样本（2026-09-09 起）足够后再比。

**`citable` 的含义**：fresh ledger + 14 项断言全通过 + 参数与配置账户一致 + 无 `--set` 覆盖。
它保证"这条数字的装配与数据是健全的"，**不等于"样本外"**——2026 窗口仍是 IS（已被多轮
参数选择触碰），`citable=true` 只说明它的数据/装配没问题。

**结论（2026-09-09 审计 P-1）**：2025 窗口的"11/11 通过"是**假象**——
`minute_coverage` 报 100% 是**日期级**指标，而实测每天只有 **274/800（34%）** 标的带分钟特征
（2025-10-27→12-12 共 35 天，沪市 468 只全缺），且 **107 笔成交里有 45 笔落在这些低覆盖日**。
新探针已把这两点变成断言，窗口现在正确地判为 **不可引用（citable=false）**；5 个旧工件已标记
`data_coverage_invalid: true`。回补脚本 `scripts/backfill_minute_gap.py` 已就绪（干跑确认
API 仍提供该窗口），**收盘后执行**，之后重跑本窗口至 `citable=true`。

**方法论披露（审计 P-2）**：`flat_3p5` 是在**这个 OOS 窗口上被选出来的**（`selection_window:
OOS-2025H2`），因此该窗口不再是干净的样本外；2026（IS）同样已被用于多轮选择。**部署配置的
前向观测数 = 0**，"先定规则"的说法没有预注册产物可证，本文不以此辩护，只按事实标注。

**2025 OOS 窗口的数据约束（必须与数字一起读）**：82 个交易日中有 **35 天**
（2025-10-27 → 2025-12-12）分钟特征包只有 **约 274/800 只标的**（其余天最多 799 只）。
尾盘量比门槛对缺失值判定为"不通过"，因此这 35 天里约 2/3 的截面被挡在入场之外——
OOS 数字是在"截面残缺"条件下得到的，不能代表完整截面的策略表现。

**限价锁定的判定是方向感知的**（与执行器同一规则）：买入涨停价、卖出跌停价才违规；
卖出涨停价（有买盘）合法，不得误报。首版断言用方向无关的 `limit_lock_mask`，
把 3 笔涨停价卖出误判为违规（2026-01-09 002625.SZ / 2026-03-02 601857.SH /
2026-04-10 605117.SH），已修正。

### 已发现的窗口约束

分钟缓存覆盖 2025-09-01 → 2026-09-08（800 标的、平均 224.5 天、527/800 覆盖率
<90%），其中 **2025-10-27 → 2025-12-12 有连续缺口**（每日仅 526–527 只标的）。
AlphaFeed 分钟接口下界约 2025-08-01（2023/2024/2025H1 返回空）。因此：

- OOS 窗口只能取 **2025-09-01 起**，且必须避开缺口（脚本断言会拦住）；
- 覆盖率 <90% 的标的在缺日会被"缺日=FAIL"的门槛挡掉入场，OOS 数字须同时报告
  覆盖率。

## 七、研究/生产同构（审计 2.1）

因此：

## 九、当前结论（2026-09-10 收盘后重写；含 800 只股票池更正）

1. **部署口径**（固定 3.5% 止损 + 分钟收盘确认 + 开盘 30 分钟豁免 + 尾盘量比门槛 +
   满仓化 + 现金约束）：补成**真实 800 只股票池**后，IS 2026 段
   **+5.72% / Sharpe 0.67 / t = 0.53 / maxDD 8.42%**
   （`outputs/d_oos_is_2026_v5.json`，14/14 断言通过、`citable=true`）。
   此前公布的 **+16.36% / Sharpe 1.66 作废**——它是在只有 301 只标的的截面上得到的。
2. **2025 OOS 窗口（回补后，可引用）**：**+1.64%/Sharpe 0.40（t = 0.23）**，
   `citable=true`、最小符号覆盖 99.1%、零洞内成交。回补前同一配置为 +8.12%/1.58
   —— 数据洞把 OOS 结果抬高了约 6.5pp，回补后的数字才是真实口径。
3. **没有统计显著的正 alpha 证据**：IS t = 0.53、OOS t = 0.23，两个窗口现在给出
   **同一量级**（Sharpe 0.67 vs 0.40）；此前"IS 强、OOS 弱"的落差主要来自 2026 年
   被缩小的截面，而不是 regime 差异。
4. 实时执行样本 **n = 1**（2026-09-08 13:00:06 300832.SZ），远不足以评价实时层。
5. 系统保持 `deployment.mode = observe`（模拟盘），未接入任何券商接口；
   接入前置条件见 `docs/LIVE_READINESS.md`（C 项全部待补）。
6. **数据底座问题（本轮新增，优先级最高）**：
   - 2026 年价格面板只有 301 只（声明 800）→ **已回补 500 只、0 报错**，
     月度覆盖 301 → 800；新增硬闸门 `effective_universe`（补齐前 0.376 判失败，
     补齐后 1.00 通过）；
   - 全 A 入库实质停更：最新 universe 快照（2026-08-07，5,205 只）中 **4,364 只**
     在 2025-12-31 之后没有任何 bar，只有 D 轨的 800 只保持新鲜——全市场/成分研究
     已过期，D 轨本身不受影响；
   - 偏差判定改为「所有已测通道的最大值」→ **BLOCKING**（截面构成通道 9.60pp/年 =
     1.2×α），自进化闭环保持关闭。
7. **前向期不再评估 alpha**（审计 1.1–1.3）：前向窗口对 Sharpe 没有功效
   （SE = √(252/N)：SR=1.0 需 6.3 年、SR=0.5 需 25 年才够 t=2.5，而制度匹配只有 1–3 年），
   因此**能力闸门被风险闸门取代**——只评估管线跟踪误差 / 成本标定 / 运行可靠性，
   Sharpe 与 maxDD 仅记录不判定。协议见 `docs/FORWARD_PROTOCOL.md`；
   候选改为**两条重放臂**的配对检验（旧版因继承生产订单清单而结构上不可分离）。
8. **下一步（按优先级）**：
   - 用 800 只股票池**复跑止损宽度 A/B 与网格**（§三那张表的绝对值已作废，
     相对排序也未经验证）；
   - 前向积累样本（干净窗口自 2026-09-11 起）；
   - 把"实时执行"样本从 1 笔积累到至少几十笔；
   - 全市场入库恢复（4,364 只停更）或明确把研究范围收敛到 D 池。
